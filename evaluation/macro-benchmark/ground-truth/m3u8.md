## Values, as the ledger uses them

- **Playlists.** `M3U8(content, base_path, base_uri, strict,
  custom_tags_parser)` parses `content` (a str, "the m3u8 content as
  string") with `parser.parse`, a dict of dicts, lists, strs, ints, floats,
  bools and datetimes. `_initialize_attributes` builds the model objects
  from it: `Key` (`keys`), `InitializationSection` (`segment_map`), a
  `SegmentList` of `Segment`, a `MediaList` of `Media`, three
  `PlaylistList`s (`Playlist`, `IFramePlaylist`, `ImagePlaylist`), `Start`,
  `ServerControl`, `PartInformation`, `Skip`, a `RenditionReportList` of
  `RenditionReport`, a `SessionDataList` of `SessionData`, `SessionKey`,
  `PreloadHint` and `ContentSteering`. `Segment.__init__` builds its
  `PartialSegmentList` of `PartialSegment`, its `InitializationSection` and
  its `DateRangeList` of `DateRange`; `PartialSegment.__init__` its
  `DateRangeList`. The package never makes a `Tiles`, a plain `TagList` or a
  `MalformedPlaylistError`.
- **Client assignments (B2).** The `M3U8` docstring documents its
  attributes, and the tests assign `version` (int or str), `is_endlist`,
  `playlist_type`, `media_sequence`, `discontinuity_sequence`, `base_path`,
  `base_uri`, `data`, a segment's `key` (a `Key`), `base_path` and `bitrate`
  (`tests/test_model.py:649-1709`). None of these assignments puts a
  package object where the package converts or compares another class; the
  list attributes (`segments`, `media`, `playlists`, ...) are never
  assigned, so the grouped-list sites keep the lists that the package made.
  The `add_*` methods append the documented objects (the tests pass
  `Media`, `Playlist`, `IFramePlaylist`, `ImagePlaylist`, `Segment`,
  `RenditionReport` and `PartialSegment`).
- **Attribute values.** The string and number attributes (`uri`, `codecs`,
  `duration`, `bandwidth`, ...) are strs, ints, floats or None from the
  parser, or the client's values for these documented string and number
  attributes; `program_date_time` is a datetime ("as a datetime", the
  `Segment` docstring). So the `%`, `+` and f-string sites format no package
  object (the default rejection of the 25 `__str__` methods), and
  `str()` converts a package object only at the sites that name one.
- **Keys.** A segment's `key` is a `Key` that `find_key` takes from
  `M3U8.keys`, a `Key` that the client assigns, or None. `SessionKey`
  inherits every method of `Key`, so admitting it as a key adds no edge.
  `Key` and `InitializationSection` define `__eq__` and `__ne__` (and so no
  `__hash__`).
- **The HTTP client.** `load(uri, ..., http_client=DefaultHTTPClient())`:
  the default instance is made at import (`__init__.py:86`, the edge
  `m3u8 -> DefaultHTTPClient.__init__`). A client's own `http_client` is
  opaque (B5).

## Judgement calls

**J1. The `base_path` and `base_uri` properties.** `BasePathMixin` defines
`base_path` (getter and setter, one node) and `absolute_uri`; `Segment`
overrides `base_path` and defines `base_uri`; `M3U8` defines both; the
grouped lists get write-only properties from `GroupedBasePathMixin`
(`property(None, _set_base_uri)`, `property(None, _set_base_path)`,
`mixins.py:44`, `50`). Every other class stores `base_uri` as a plain
instance attribute.
- `Segment.base_path`'s getter loads `super().base_path`: the getter of
  `BasePathMixin` (`model.py:688:24`). Its setter calls
  `super(Segment, self.__class__).base_path.fset(self, newbase_path)`
  (`692:54`): `super` bound to a class returns the property object itself
  (`property.__get__` with no instance), so the load at `692:40` runs no
  getter, and the explicit `fset` call is the edge
  `Segment.base_path -> BasePathMixin.base_path`.
- In `BasePathMixin.base_path`, `self.base_path` (`mixins.py:33:25`,
  `36:50`) is the Segment's own property when the setter runs on a Segment
  (through that `fset` call) and `BasePathMixin.base_path` for the other
  classes: both callees, as the trace has them.
- `absolute_uri` loads `self.base_uri`: `Segment.base_uri` for a Segment;
  for the other classes a plain attribute (`mixins.py:11:28`, `12:17`,
  `12:49`).
- `_set_base_uri` stores `item.base_uri`: only a `SegmentList`'s elements
  have a setter (`Segment.base_uri`); `_set_base_path` stores
  `item.base_path`: `Segment.base_path` or `BasePathMixin.base_path`.
The alternative, `M3U8.base_uri` or `M3U8.base_path` at these sites, needs
an `M3U8` in a grouped list or as a `BasePathMixin` receiver: nothing puts
one there.

**J2. backports-datetime-fromisoformat (`parser.py:9-14`).** The import
of `backports.datetime_fromisoformat.MonkeyPatch` is optional (`except
ImportError`), so both sides run (README, Judgements). The release declares
the backport for Python before 3.11, so it is installed on the admitted
CPython 3.7 to 3.10 and the call runs there: the edge
`m3u8.parser -> backports.datetime_fromisoformat.MonkeyPatch.patch_fromisoformat`
(`12:36`). The trace (3.14) does not install it, so it is a missing module
of the benchmark; its access path and its defining path are the same name.
Read, never run, from the sdist of 2.0.1 (the newest release on or before
m3u8 6.0.0's upload), SHA-256
`1b6afca7f47019c22df43062cde73c1af65fbdebc66520f352c690d52fd27127`
(`deps/pypi/backports-datetime-fromisoformat-2.0.1/backports/datetime_fromisoformat/__init__.py:7-38`):
on 3.x before 3.11, `patch_fromisoformat` writes the C functions
`datetime_fromisoformat`, `date_fromisoformat` and `time_fromisoformat`
into the type dicts of `datetime`, `date` and `time` and flushes the type
cache through ctypes; it calls no package code. `cast_date_time` then calls
that function through `datetime.fromisoformat` (`27:34`); a function
installed at a public outside attribute keeps the attribute's path
(clarifications of the full audit, "Outside names"), so the callee is
`datetime.datetime.fromisoformat` on every admitted version. Alternative:
leave out the `patch_fromisoformat` edge because the benchmark's
environment lacks the library; but the rule on optional imports and the
declared requirement admit it (1 outside edge).

**J3. `urlsplit` (`__init__.py:93:16`; `mixins.py:12:43`, `15:24`).**
`urlsplit` is a plain function on 3.7 to 3.10 and an `lru_cache` wrapper
from 3.11: both names, as fastjsonschema's `ref_resolver.py:52` and `64`
(README, "Callees outside the package"). The trace (3.14) has the wrapper;
`load -> urllib.parse.urlsplit` and `absolute_uri -> urllib.parse.urlsplit`
come from reading (2 outside edges). `urljoin` is a plain function on every
admitted version; the `urlsplit` that it calls inside is library code.

**J4. The response of `DefaultHTTPClient.download` (`httpclient.py:11-27`).**
`download` builds an opener with `urllib.request.build_opener`, whose
default handlers (`deps/cpython/3.7.17/Lib/urllib/request.py:585-587`,
the same list in 3.15.2) open http and https URLs into an
`http.client.HTTPResponse` and file, data and ftp URLs into a
`urllib.response.addinfourl` (`FileHandler.open_local_file`,
`DataHandler.data_open`, `FTPHandler.ftp_open`; `request.py:1521`, `1671`,
`1581` in 3.7.17). `load` accepts any URI with a scheme
(`__init__.py:93`), and the client's URI decides the scheme: every scheme
that the default opener handles is admitted. So:
- `resource.geturl()` and `resource.info()`: `http.client.HTTPResponse.*`
  and `urllib.response.addinfourl.*` (`addinfourl.info` is inherited from
  `addinfo` and named by the receiver's class);
- `resource.info().get(...)` and `resource.headers.get_content_charset(...)`:
  the headers are an `http.client.HTTPMessage` (`parse_headers`) or an
  `email.message.Message` (`email.message_from_string` in the three
  handlers): `http.client.HTTPMessage.get`, `.get_content_charset` and
  `email.message.Message.get`, `.get_content_charset`;
- `resource.read()`: `http.client.HTTPResponse.read`, and for an
  `addinfourl`, whose base `urllib.response.addbase` is a
  `tempfile._TemporaryFileWrapper` (`response.py:14` in 3.7.17 and 3.15.2),
  the local `func_wrapper` that `_TemporaryFileWrapper.__getattr__`
  returns: `tempfile._TemporaryFileWrapper.__getattr__.func_wrapper`
  (asciinema's and anytree's name);
- the bytes are decoded: `<builtin>.bytes.decode`; `gzip.decompress`.
The tests patch `OpenerDirector.open` with a Mock (J12), so the trace has
none of these: 10 outside edges come from reading. Five of them rest on
the non-http schemes (`addinfourl.geturl`, `addinfourl.info`,
`Message.get`, `Message.get_content_charset`, `func_wrapper`); the
alternative, http and https only, would drop those five: the README and
the docstring say "uri", and nothing restricts the scheme. An HTTP error
status raises `urllib.error.HTTPError` in the opener
(`HTTPErrorProcessor`), so no error response reaches these calls.

## Notes for the auditor

- `_parse_cueout_cont` tests `duration` where it means `scte35`
  (`parser.py:579`); it changes no call.
- `Tiles.dumps` concatenates `self.duration`, which the parser makes a
  float: a `Tiles` built from parsed values would raise `TypeError`; the
  package never builds one (J11).
- `HTTPSHandler.__new__` returns a `urllib.request.HTTPSHandler`, so
  `HTTPSHandler(...)` never runs an `__init__`, and the call
  `urllib.request.HTTPSHandler(context=context)` (`httpclient.py:36:43`)
  is the library class, not a recursion.
- `MalformedPlaylistError` is never raised; `Key` and
  `InitializationSection` are unhashable (they define `__eq__` only).
- `property(None, _set_base_uri)` and `itertools.repeat(remove_quotes)` pass
  package functions to library code that stores them: no call-back.
- `Segment.__init__` ignores its `key` parameter (the parser's dict) and
  keeps `keyobject`.
