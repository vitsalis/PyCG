## Architecture, as the ledger uses it

- `javascript.py` holds the public API: `to_html_datatable`,
  `to_html_static_preview`, `to_markdown_table`, `show`,
  `init_notebook_mode`, `get_itable_arguments` and
  `get_itables_extension_arguments`. `get_itable_arguments` converts the
  frame (1139-1198), fills the options from `itables.options`
  (`set_default_options`), downsamples (`downsample.py`), builds the header
  (`_table_header`) and the rows (`datatables_format.datatables_rows`). The
  options travel as the `**kwargs` dict, returned as `dt_args`.
- `options.py` replaces the class of its own module with
  `_ITableOptionsModule` (237), whose `__setattr__` checks options that a
  client sets.
- `typing.py` defines the TypedDicts of the options, `JavascriptFunction`
  and `JavascriptCode` (str subclasses), and a fallback for `NotRequired`
  and `Unpack` (J1).
- The integrations (`shiny.py`, `streamlit.py`, `widget/`,
  `itables_for_dash/`) call `to_html_datatable` or
  `get_itables_extension_arguments`. `itables_for_dash/ITable.py` is a dash
  component generated by `dash-generate-components` (J4).
- The current trace records 2,447 passed, 8 skipped and 2 deselected tests,
  with 571 edges. Its configured scope contains all 16 test files, including
  `tests/test_downsample.py`; pyarrow and tzdata are installed, and the
  time-zone case is no longer deselected. The source audit also checks
  calls that the recorded tests do not exercise, including dataframe
  alternatives and the `type(df)(...)` fallback in `downsample.py`.
  `itables_for_dash` cannot be imported in the test environment (dash is
  not installed): it stays analysed source, and its edges come from
  reading only. 104 of the 129 functions run. The notebook, widget,
  streamlit, shiny and dash code never runs.

## Scope rules

**A. Edges are per function.** Every function keeps the edges of its body.
`_raise_if_javascript_code` (`javascript.py:1386`) has no caller in the
package; its parameters are judged as for a public function (B), so its
`values.items()` after `isinstance(values, dict)` is `<builtin>.dict.items`.

**B1. Receivers.** The only package classes with methods called on `self`
are `widget.ITable` (`self.update`, the property `self.style`) and
`_ITableOptionsModule`. Client subclasses are client code.

**B2. Arguments.** The option dicts are package values: the `**kwargs` of
the API functions, and `ITableOptions`/`DTForITablesOptions` (TypedDicts,
dicts under B4). Method calls on them are `<builtin>.dict` methods. The
column definitions of `columnDefs` are the dicts that
`get_itable_arguments` adds (1301-1321) and client Mappings (opaque).

**B4. Concrete outside types.** See "Data frames" below. Also: path
instances constructed by `Path`, returned by `Path.cwd` or obtained by
path operations use `pathlib.PosixPath` or `pathlib.WindowsPath` methods;
explicit `Path` constructors and class methods retain that class path; `style` is
a str after `set_default_options` (1539-1543), so `_caption_side` calls
`<builtin>.str.split`; `selected_rows` is a sequence of ints.

**B5. Client objects are opaque.** A client Mapping as `style`
(`get_expanded_style`, `get_compact_style` beyond J5) and a client column
definition have no outside callee.

**C. Public.** Every module of `itables` without an underscore is public,
so `datatables_format.datatables_rows`, `downsample.nbytes`,
`downsample.downsample`, `javascript.safe_reset_index` and the other
helpers without an underscore take what a client can pass: the documented
frame types.

## Data frames

`DataFrameOrSeries` is annotated `Any`, and its docstring
(`typing.py:54-57`) documents "A Pandas or Polars DataFrame or Series, a
numpy array, or a Pandas Style object". `docs/other_dataframes.md` adds a
pyarrow Table and a modin DataFrame through narwhals. B4 takes these
documented concrete types. The package branches on the module name of the
class (`get_dataframe_module_name`, `typing.py:85`) and on the class name;
in each branch a method call names the classes of that library that can
reach it:

- module `pandas`: a DataFrame or a Series (a Styler has no `items`),
  `pandas.DataFrame.items` and `pandas.Series.items` at
  `datatables_format.py:298`, `downsample.py:18`, `javascript.py:1092`;
  a Styler only at `javascript.py:1334-1344`;
- module `polars`: `polars.DataFrame`, `polars.Series`
  (dtype methods use each concrete exported dtype class);
- frames that the package makes with `narwhals.from_native`
  (`datatables_format.py:316`, `javascript.py:1055, 1106, 1198`):
  `narwhals.DataFrame` and its columns `narwhals.Series`.

After the conversions of `get_itable_arguments`, the private functions get
only a pandas DataFrame, a polars DataFrame or a narwhals DataFrame (a
Series became a frame at 1165, a numpy array a pandas DataFrame at 1162,
keeping the module name `numpy`). Method calls on the columns and indexes
name the pandas or polars class (`pandas.Series.tolist`,
`pandas.Index.tolist`, `pandas.Index.get_level_values` and
`pandas.MultiIndex.get_level_values`, plus the supported concrete Index
subclasses). Calls on objects that the package
makes in `sample_pandas_dfs.py` and `sample_polars_dfs.py` name the class
that the library returns. An inherited implementation name in the trace
may alias several concrete receiver classes. Matching such an alias does
not prove that every class ran; source evidence decides the receiver set.

## Judgement calls

1. **J1. The fallback `_SubscriptableFallback`** (`typing.py:26-40`).
   `from typing import NotRequired, Unpack` fails before Python 3.11; then
   `from typing_extensions import NotRequired, Unpack` is tried, and if it
   fails too, `NotRequired` and `Unpack` are instances of
   `_SubscriptableFallback`, whose `__getitem__` returns `Any`. The default
   (version branch runs if a supported version takes it; both sides of an
   optional import run) applies: on 3.9 and 3.10 without a typing_extensions
   that has both names, every `NotRequired[...]` in the TypedDict bodies
   (74 sites, `typing.py:129-250`; class-body annotations are evaluated
   before 3.14) and every `Unpack[...]` in a signature (13 sites; no module
   has `from __future__ import annotations`) calls
   `_SubscriptableFallback.__getitem__`: 7 edges from the module nodes
   `itables.typing`, `itables.javascript`, `itables.shiny`,
   `itables.streamlit`, `itables.widget`, `itables_for_dash`,
   `itables_for_dash.properties`. The default rejection covers the 706
   other sites. The lead's ruling: the 4 edges of the framework modules
   stay, because the versions of a dependency that the package admits are
   decided by the package's own declared requirements, not by those of other
   libraries. Background: the first three modules import nothing
   outside the package, so their edges are certain. `itables.streamlit`,
   `itables.widget` and the two dash modules also need streamlit, anywidget
   or dash (and `ITable.py:4` imports `typing_extensions` itself, which then
   must lack only `Unpack`: typing_extensions 4.0 had `NotRequired` but,
   as far as I know, not `Unpack`); itables admits any typing_extensions
   version (extras `typing`, `dash`). The two
   `_SubscriptableFallback()` calls (`typing.py:39-40`) have no edge (no
   `__init__`).
2. **J2. Data frame types by documentation** (B4): see "Data frames".
   The lead's ruling: an annotation of `Any` states no type (PEP 484 gives
   an unannotated parameter the type `Any`), so the documentation of the
   alias can fix a concrete outside type under B4. The
   tests pass narwhals frames too; test values do not fix a type, but the
   package branches on the module name `narwhals` itself (J3).
