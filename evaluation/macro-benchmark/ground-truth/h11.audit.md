# h11: audit of the ground truth

Historical audit. The global-rule audit of 2026-11-15 (audit record `2026-11-15/README.md`)
records the later corrections and current graph counts.

Independent audit of `h11.ledger` (h11 v0.16.0, commit `1c5b075`). I read
the whole package before I opened the ledger. I did not run, import or
install the package, and I used no static-analysis output. The trace
(`dynamic/h11.json`) served only as a lower bound. I judge the ledger by
the lead's final scope rules A, B1-B5 and C.

## Result

The ground truth is complete and correct: no missing edge, no wrong edge
and no wrong name. **One finding stands:** A3, a wording fix of one
rejection reason.

Three findings are closed:
- A1 and A2 are withdrawn by rule B5.
- A4 is resolved in favour of the ledger by the lead's ruling on Q4.

Every dispatch table, special method, property, dead-code claim and
default rejection checked out.

## Decisions on arguments

### `Headers` passed back in as `headers=`

This use is in scope by rule B2, for three reasons:
- **Annotation:** all three constructors annotate `headers` as
  `Union[Headers, List[...], ...]` (`_events.py:86, 140, 340-342`).
- **Code:** each constructor stores a `Headers` as it is, in an explicit
  `isinstance` branch (`_events.py:92-93, 147-148, 348`).
- **The package does it itself:** `_connection.py:654-655` calls
  `Response(headers=headers)` with a `Headers` (`response.headers` or the
  value of `set_comma_header`).

The class docstring also shows client code that compares
`r.headers == [...]` (`_headers.py:92`).

The use adds no edge:
- Each site that receives the argument tests `isinstance` first. It calls
  `normalize_and_validate` only for a value that is not a `Headers`.
- Every downstream site that touches `event.headers` gets a `Headers` in
  every execution anyway, and its `Headers` callees are in the ledger:
  - `_events.py:113:28`: `__getitem__`, through the `Sequence.__iter__`
    mixin.
  - `_writers.py:97:12` and `121:12`: `__bool__`.
  - `get_comma_header`, `set_comma_header` and `write_headers` read
    `_full_items` directly and call no method.

## Final scope rules: what they change

- **Rule A (edges are per function).** No out-edge of the three dead
  functions was dropped because they are dead. Their bodies are only
  `pass`, so they have no out-edges:
  - `_ResponseBase.__post_init__` (`_events.py:168-169`)
  - `BodyWriter.send_data` (`_writers.py:71-72`)
  - `BodyWriter.send_eom` (`_writers.py:74-75`)

  The other functions without a package caller keep all their out-edges in
  the graph: `Headers.__repr__` has 4 and `Headers.__eq__` has 3. No ledger
  rejection relies on reachability. The three rejections that mention
  instantiation are receiver arguments (B1). The others are value
  arguments (B2-B5).
- **Rules B1 and C (receivers).**
  - **`BodyWriter` as a bare receiver.** `BodyWriter` (`_writers.py:62`) is
    a plain class: it has no `abc` base and no abstract method, so it can
    be instantiated. But it is private by rule C:
    - its node name `h11._writers.BodyWriter` has the component `_writers`;
    - `_writers.py:17` exports only `WRITERS`;
    - `h11/__init__.py` does not re-export it;
    - no document mentions it.

    So only the package creates instances, and it creates only the three
    subclasses (`_connection.py:334`, from `WRITERS[SEND_BODY]`). Rule B2
    agrees: the only package call of a writer, `_connection.py:571`, gets
    its values from `WRITERS` (two functions and the three subclasses), and
    no documented API takes a writer. So a bare `BodyWriter` never reaches
    `BodyWriter.__call__`. The rejections of `BodyWriter.send_data` and
    `send_eom` at `_writers.py:65:27` and `67:26` stand.
  - **`_ResponseBase`** (`_events.py:129`) is private by its own name and
    not abstract. The package never instantiates it, so the rejection at
    `_events.py:166:27` stands.
  - **`h11.Event`** is public and has no abstract method, so a client can
    pass `Event()` to `Connection.send` (annotation `Event`). I traced that
    value through `_process_event`, `_server_switch_event` and
    `ConnectionState.process_event`. It ends in the `KeyError` branch of
    `_fire_event_triggered_transitions`, whose edges the ledger has. It
    adds no edge.
- **Rule B4 (annotated outside types).** It adds nothing, so there are no
  findings of kind "convention".
  - Five explicit method calls are on a parameter whose annotation fixes
    an outside type. The ledger names that type's method at each one:
    - `regex.fullmatch` (`Pattern[bytes]`): `re.Pattern.fullmatch`
    - `msg.format` (`str`): `<builtin>.str.format`
    - `s.encode` (`str` after `isinstance`): `<builtin>.str.encode`
    - `name.title` (`bytes`): `<builtin>.bytes.title`
    - `io_dict.get` (`Dict`): `<builtin>.dict.get`
  - Two calls are on annotated stored attributes, and the ledger names
    them too: `pending_switch_proposals.add` (`Set`) and `states.update`
    (`Dict`).
  - The 11 `write(...)` calls go through a bare callable (`Writer =
    Callable[[bytes], Any]`). The package supplies the value
    `data_list.append`, so `<builtin>.list.append` is right.
  - In two places the annotation says `bytes` but the package passes
    `bytearray`s: `_obsolete_line_fold(lines: Iterable[bytes])` and
    `Data.data`. No method is called on those values, so the rule meets no
    conflict.
- **Rule B5 (client objects are opaque).** It withdraws A1 and A2, and it
  gives the wording for A3. It changes no other site. The other
  client-facing rejections already treat client objects as opaque: the
  `Data.data` placeholder at `_writers.py:89, 105, 107`, and the operand
  `other` of `Headers.__eq__`. The callees accepted at `list(other)`
  (`_headers.py:111:34`) are still right. There, `other` can be the
  `Headers` of another event: when a client compares two events, the
  generated `__eq__` passes it.

## Step 2: default rejections

- `Headers.__getitem__` decides 254 sites, and `Headers.__eq__` decides 265.
  I examined **all 519 site decisions**, not only a sample:
  - 158 sites of each default are `typing` subscripts: annotations, type
    aliases, `cast(...)` arguments and the base of `Headers`. I checked them
    by node and by name (`Type`, `Union`, `Tuple`, `List`, `Dict`, `Optional`,
    `Callable`, `Iterable`, `Literal`).
  - The rest are runtime sites: 96 for `__getitem__` and 107 for `__eq__`,
    in all modules, `_headers.py`, `_events.py` and `_connection.py`
    included. I read each one in the source. At none of them can an operand
    be a `Headers`. The operands are lists, tuples, dicts, sets, bytes,
    bytearrays, ints, strs, sentinel classes, event classes and a
    `ReceiveBuffer` (`bytes()` uses its `__bytes__`). `list(self) ==
    list(other)` (`_headers.py:111:27`) compares two lists.
- **Dataclass `__eq__`.** By the micro-benchmark case
  `stdlib_classes/dataclass_order`, a package comparison of two events of
  the same class would reach `Headers.__eq__` from the comparing scope. The
  only package site that compares an event is `event not in [NEED_DATA,
  PAUSED]` (`_connection.py:482:22`). There the other operand is a sentinel
  class. Its `__class__` is the sentinel itself, so the generated `__eq__`
  returns `NotImplemented` before it compares fields. `Headers.__eq__` has
  no package caller, and the ledger is right.
- Both default reasons are true. One nit: the `__getitem__` reason lists
  `re.Match` among the subscripted operands, but no site subscripts an
  `re.Match`. `match.span(0)[-1]` subscripts a tuple, and `matches[...]` is
  the dict from `groupdict()`.

## Why the trace confirms nearly all edges

The 98% trace coverage does not hide missing edges here. h11's test suite
targets full line coverage, and 85 of the 89 functions run. Only 4
functions never run: `Headers.__repr__` and the three dead-code methods.
Because every call site has an entry, a missing edge could only come from
a value that no test passes at a covered site. I searched for such values
at every polymorphic and implicit site (steps 2, 3 and 5). The only
candidates came from client iterables passed as `headers=`, and rule B5
makes them client behaviour.

## Open questions about conventions

- **Q1 (resolved by rule B5):** a library object that the client builds
  around a package object is opaque. A1 and A2 are withdrawn.
- **Q2 (resolved by rules B1 and C):** `normalize_and_validate` is a
  private entry point, so a direct `Headers` argument is out of scope.
- **Q3:** the documented type and the annotation of an argument can
  differ: "any iterable of pairs" against `List[Tuple[...]]`. Rule B2 takes
  their union. The writer's line 4 says "documented types" but applied the
  annotation at `158:24`. With rule B5 the difference changes no edge
  here, only the reason (A3).
- **Q4 (resolved by the lead):** when a parameter has an annotation, the
  annotation decides which package values fit the role (B2). B3's "never
  produces for that role" applies only where no annotation or documented
  type exists. Mechanical rules beat judgement about intent.
  `Connection.__init__ -> Sentinel.__repr__` stays (A4 closed).

No convention question remains open.


## Fourth source audit (2026-11-16)

A fresh source-first audit read the 11 runtime modules and supporting tests,
documentation, metadata and CI before the baseline. The required benchmark
README's h11 examples and aggregate counts were the only prior exposure.
The source model and inventory were frozen before comparison (freeze SHA-256
`2a5056abebead0d03494605f7c298a34a7d131380d2d2a3070c341d91c87a8e5`).

All 285 baseline pairs, 1,158 AST sites (759 ledger-relevant), 472 ledger
entries, 100 graph bodies, default rejections and exclusions were checked.
The 20 zero-callee bodies remain. The earlier audit above is retained as a
record of its time; its historical counts and reasoning are not current rules.

The proposal retains every baseline pair and adds four outside pairs:
normalize_and_validate and get_comma_header each call str.lower and str.split.
These occur at _headers.py:171/196, 173, 248 and 249. Under standard -O/-OO,
the public event constructors' _parsed=True keyword can bypass conversion and
the removed assertions permit their annotated string header pairs. An admitted
str-subclass name can control header-name equality while its result stays
opaque. A fully constructed Request then supplies concrete string values to
get_comma_header through the public send API. str.split binds successfully
and raises inside its builtin body on a bytes separator; str.strip is not
reached. No failed object is reused. Current h11.md judgement 12 and the ledger
retain the exact witnesses. Ordinary execution's existing edges remain.

The root explicitly adopted standard optimized execution as a configuration
assumption after an optional scope question had no reply; this was not a user
answer. No runtime __debug__, __doc__, or getdoc path exists. All 18 assertions
were reviewed; no further optimized target was found. CPython and explicitly
supported PyPy are covered from Python 3.8, without a classifier upper bound.

Result: 100 nodes, 289 edges (150 package, 139 outside), 0 false positives,
4 false negatives corrected. The trace confirms 280; 9 are reading-only;
the one private-input trace rejection stays. Static check.py and --origin
pass against scratch staging. No target or PyCG code was run, and no live
evaluation file was edited.
