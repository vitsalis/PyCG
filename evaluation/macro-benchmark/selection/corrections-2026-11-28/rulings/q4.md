# Q4. Missing-library results: access paths against classes

Adopted by the lead in place of a referee, maintainer's instruction of
2026-11-28. Read at `c7fc8fb3`. Paths are relative to
`evaluation/macro-benchmark/`; a package's files are cited from its root
under `projects/<name>/`, its ground truth is under `ground-truth/`, and
`benchmark-rules.md:<n>` is a line of `evaluation/benchmark-rules.md` at
that commit.

**1. The question.** The study saw two naming schemes for the methods of
numpy results, and asks whether one of them is wrong:

| Package | Site | Callee in the ledger |
|---|---|---|
| face_classification | `utils/data_augmentation.py:214:51` `image_array.astype('uint8')` in `ImageGenerator.flow` | `numpy.clip.astype` (ledger 1267) |
| face_classification | `utils/grad_cam.py:101:34` `np.clip(x, 0, 255).astype('uint8')` in `deprocess_image` | `numpy.clip.astype` (ledger 1562) |
| face_classification | `utils/preprocessor.py:6:17` `x.astype('float32')` in `preprocess_input` | `cv2.resize.astype`, `numpy.asarray.astype`, ... (ledger 1708-1709) |
| pgvector | `pgvector/bit.py:45:37` `value.astype(bool)` in `Bit.__init__` | `numpy.ndarray.astype` (ledger 118) |
| uncertainties | `unumpy/core.py:81:24` `arr.view(numpy.matrix)` in `unumpy_to_numpy_matrix` | `numpy.matrix.view` (ledger 1445) |

**2. The ruling.** **Apply the missing-module rule of "Callees outside
the package": a library that the project's test environment does not
install is named by access paths; an installed library by the receiver's
class.** The two schemes are the two branches of one rule, the difference
between a project without numpy and projects with numpy. Nothing in the
ground truths contradicts the rule.

Effect: no edge added, removed or renamed in any package; no text of
`benchmark-rules.md` changes.

**3. What the rules say.**

- "Callees outside the package" (Ground-truth conventions): "A call into
  a third-party module that is not installed is named as a missing module
  by the micro-benchmark rules (markdown2: `wavedrom.render`), also when a
  copy of the library can be read". "Installed" is the test environment:
  `test-environments/<name>.installed.txt` is "What the container of the
  trace had installed" (Layout).
- Clarifications 2026-11-15, "Missing libraries": "Subscript, unpacked and
  arithmetic results have no inferred stub path; direct attribute/call
  chains retain their imported access path." Batch 7, "A stub result keeps
  its path through assignment (einops)": a missing-library result keeps
  its access path through assignment, storage and forwarding; "Concrete
  input-type evidence supplies independently admitted class paths; it
  does not replace a produced stub's path".
- For an installed library the ordinary rule holds: "A method of an
  outside object is named by the class of the receiver, also when that
  class inherits it".

The rules decide it.

**4. The evidence.**

| Package | numpy in the environment | Names used |
|---|---|---|
| face_classification | no environment at all: no tests, keras 2.0.5 and tensorflow 1.1.0 do not install (`projects.toml` notes; `face_classification.md:9-13`) | access paths only: 134 numpy callees, none a class method (`numpy.asarray.reshape.astype`, `numpy.clip.dot.mean`, ...) |
| pgvector | `numpy==2.5.3` (`test-environments/pgvector.installed.txt:5`) | classes: `numpy.ndarray.astype`, `.tobytes`, `.tolist` |
| uncertainties | `numpy==2.3.2` (`test-environments/uncertainties.installed.txt:5`) | classes: `numpy.ndarray.view`, `numpy.matrix.view` |
| einops, itables, jsonpickle, textdistance | installed | classes (`numpy.ndarray.mean` is einops ledger 612 and textdistance ledger 1847) |

A sweep of every ledger with a `numpy.` callee found no package that names
a numpy class method without numpy installed, and none that uses a numpy
access path with numpy installed. The 2026-11-15 audit of
face_classification applied the rule explicitly: "Do not infer ndarray,
model, axes, backend-function or uploaded-stream classes"
(`face_classification.md`, Global-rule audit).

The same split holds for other libraries: tablib installs PyYAML 6.0.3 and
names the rows of `yaml.safe_load` as `<builtin>.dict.values`
(`tablib.ledger:1510`); jsonpickle does not install PyYAML and names
`yaml.safe_load.get` (Q5).

**5. Against.** The name of a numpy call then depends on the environment
that a project could build, not on the program, so one expression gets
different callee names in two projects. The rules accept that on purpose
(markdown2, dagster-pipes, bottle, pyrate-limiter keep access paths "also
when a copy of the library can be read"); a scorer that wants a
tool-independent comparison can restrict the score to the edges inside
the package.
