# Q5. Results typed `Any`: `yaml.safe_load.get` against `<builtin>.dict.get`

Adopted by the lead in place of a referee, maintainer's instruction of
2026-11-28. Read at `c7fc8fb3`. Paths are relative to
`evaluation/macro-benchmark/`; a package's files are cited from its root
under `projects/<name>/`, its ground truth is under `ground-truth/`, and
`benchmark-rules.md:<n>` is a line of `evaluation/benchmark-rules.md` at
that commit.

**1. The question.** `yaml.safe_load` and `json.loads` are both typed as
returning `Any` in typeshed, but the ground truths name a `.get` on their
results differently. The sites are jsonpickle's numpy and pandas
handlers, which call `data.get(...)` on the decoded document:

| Site | Caller | Callees (ledger) |
|---|---|---|
| `ext/numpy.py:96:24` `data.get('writeable', True)` | `NumpyNDArrayHandler.restore_flags` | `<builtin>.dict.get`, `ujson.loads.get`, `yaml.safe_load.get`, `ujson.loads.get.get`, `yaml.safe_load.get.get` (`jsonpickle.ledger:375-383`) |
| 16 further `data.get` sites in `ext/numpy.py`, `ext/pandas.py` and `handlers.py` (`:271:20`) | the restore methods | the same pattern (`jsonpickle.ledger:435`, `442`, `459`, `583`, `590`, ...) |

In total jsonpickle has 31 site-callee entries rooted at `yaml.safe_load`
(17 `.get`, 9 `.get.get`, 2 `.items`, 1 `.setdefault`, 1 `.startswith`,
1 `yaml.dump.encode`) and the same 31 rooted at `ujson`. The decoders come
from `backend.py:238`, `self._decoders[name](string, ...)`, which holds
`json.loads`, `simplejson.loads`, `ujson.loads` and `yaml.safe_load`
(`backend.py:95-103`).

**2. The ruling.** **Apply the missing-module rule and the batch-7 einops
and websocket-client rulings: a loader's result is named by the class of
what it returns when the library is installed or in the standard library,
and by its access path when the library is not installed; an `Any`
annotation decides neither.** At a site that several backends reach, the
names are the union (jsonpickle's `<builtin>.dict.get` from json and
simplejson beside `yaml.safe_load.get` and `ujson.loads.get`).

Effect: no edge added, removed or renamed; no text of
`benchmark-rules.md` changes.

**3. What the rules say.**

- "Callees outside the package": "A call into a third-party module that
  is not installed is named as a missing module by the micro-benchmark
  rules".
- Batch 7, "A stub result keeps its path through assignment (einops)": "A
  missing-library result retains its access path through assignment,
  storage in package-created containers, and forwarding through package
  functions". Batch 7, pgvector: "An annotation constrains admitted types;
  it does not rename an admitted stub value when package code forwards
  it."
- Batch 7, websocket-client: a stub result "may take either outcome of a
  concrete-type `isinstance` test; on the successful branch, B4 supplies
  the concrete type's method name without erasing the result's retained
  missing-module access path."
- Batch 8, honcho J6: "the missing-module convention fixes how a missing
  library's callees are named, not what the library does".
- For an installed or standard library the receiver is named by its class
  ("A method of an outside object is named by the class of the
  receiver").

The rules decide it; the `Any` return annotation plays no part.

**4. The evidence.**

- jsonpickle's environment installs simplejson 4.2.0 and does not install
  PyYAML or ujson (`test-environments/jsonpickle.txt:24-28`;
  `test-environments/jsonpickle.installed.txt`). So `json.loads` and
  `simplejson.loads` are read, and their result at these sites is a
  `dict` (the handlers restore a JSON object): `<builtin>.dict.get`.
  `yaml.safe_load` and `ujson.loads` are missing modules:
  `yaml.safe_load.get`, `ujson.loads.get`.
- `data.get('base')` (`ext/numpy.py:327`) returns another stub value that
  `self.context.restore` forwards back to the handler (line 333), so its
  `.get` is `yaml.safe_load.get.get` (one forwarding, no loop: a finite
  path). Corrected by `n5a.md` (the audit's N5a): the forwarding repeats,
  since a base can itself be a view (numpy keeps a view's base across a
  change of subclass), so the path is an open path set, recorded to
  `yaml.safe_load.get.get.get`; the ruling above and its no-change effect
  stand for the question Q5 asked.
- The same split holds elsewhere: bottle (no ujson installed) names
  `ConfigDict.load_dict`'s `source.items()` as `<builtin>.dict.items` and
  `ujson.loads.items` (`bottle.ledger:3148-3151`); itables (no tomli
  installed) names `tomli.load.get` beside `<builtin>.dict.get`
  (`itables.ledger:3162-3166`); tablib (PyYAML 6.0.3 installed) names the
  rows of `yaml.safe_load` by class, `<builtin>.dict.values`
  (`tablib.ledger:1510`).
- A sweep of every ledger found no access path on the result of an
  installed or standard-library loader (`json.loads.get` and the like do
  not occur).

**5. Against.** PyYAML's `safe_load` of a JSON object returns a plain
`dict` on every admitted release, so naming its `.get`
`yaml.safe_load.get` looks like a missed `<builtin>.dict.get`. The honcho
ruling keeps the library's behaviour (the dict decides which branch runs)
separate from its names, and here `<builtin>.dict.get` is in the graph
anyway through the json and simplejson backends, so no edge depends on
it.
